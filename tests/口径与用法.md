# 对账表口径与用法

## 这套东西干什么

买菜单出货前的**机械判卷**：模型生成菜单，脚本判卷，不靠模型自评。

- `scripts/check_menu.py` —— 判卷器，读对账表 JSON，超预算即 FAIL
- `tests/scenarios.json` —— 场景矩阵（人群 × 菜单形态 × 约束），含大当量酒桌

## 对账表 JSON 格式

```json
{
  "人群": {"男": 3, "女": 0, "老": 2, "小": 1, "幼": 0},
  "喝酒": false,
  "控制饮食": false,
  "有主食": true,
  "场景": "配桌",
  "菜品": [
    {"名": "姜葱捞鸡", "池": "荤", "硬菜": true,
     "主料": [{"名": "鸡腿", "量": "12个（约1.2kg）"}], "蛋": 0, "汤碗": 0}
  ],
  "蛋总数": 22,
  "汤碗数": 9
}
```

- 池：只认 `荤` / `素`。主食（米饭/面）按人头另算，不进池。
- 主料 `量` 必须带克数（g/kg/斤都认），解析不到直接 FAIL。
- 蛋、汤碗可以在菜品里逐道给（`蛋` / `汤碗` 字段），也可以顶层给总数。

## 预算公式（与 SKILL.md 4.2 唯一口径）

- 当量：男 1.0 / 女 0.8 / 老 0.7 / 小 0.5 / 幼 0.3
- 大当量折减：当量 > 8 时，超出部分 ×0.8（人多尝味，人均回落）
- 修正系数（乘后封顶在 0.8–1.3）：喝酒 ×1.2｜男 >60% ×1.1｜女+老 >60% ×0.9｜控制饮食 ×0.9｜没主食 ×1.25
- 荤池 = 当量 × 180g × 修正｜素池 = 当量 × 220g × 修正
- 蛋池 = 当量 × 1.5 个｜汤池 = 当量 × 1.5 米饭碗
- 人均总量（荤+素）÷ 当量 必须落在 400g × 修正 的 ±20%

## 用法

```bash
python3 scripts/check_menu.py 对账表.json   # 退出码 0=PASS 1=FAIL
```

## 复测流程（发版闸门）

1. 改 SKILL.md 前先跑基线（预期红），红榜就是改动依据
2. 改完按 scenarios.json 重新生成各场景菜单 → 逐个过 check_menu.py
3. 全绿才允许 bump version / 推 GitHub / 发 SkillHub
4. 线上实测抓到的 bug 进下一批攒着修，不单独发版
